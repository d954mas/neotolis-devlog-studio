# Automatic speech edit

Speech edit is owned by the production agent. Studio v2 stays a deterministic
executor: it never embeds an LLM and it never opens an author approval UI.

## Agent workflow

```bash
# 1. Normalize the preserved raw take and transcribe it.
dl2 audio myreel.edits.main b01 data/recordings/b01_take.webm

# 2. Generate a hash-bound baseline. This does not modify the take.
dl2 speech-edit myreel.edits.main b01 \
  --prepare-plan data/review/b01_speech_edit_plan.json

# 3. The agent reads words.json and amends the plan, then applies it.
dl2 speech-edit myreel.edits.main b01 \
  data/review/b01_speech_edit_plan.json

# 4. The agent remaps authored word references when necessary and verifies.
dl2 check myreel.edits.main
```

There is no author checkpoint between these commands. If only conservative
mechanical cleanup is needed, step 2 may be skipped and
`dl2 speech-edit <edit> <beat>` applies the automatic baseline directly.

The baseline removes only:

- signal-confirmed long silence, while retaining short handles;
- explicit filler tokens such as `э`, `эм`, `мм`, `uh`, and `um`;
- an exact adjacent phrase restart, keeping the later take.

The agent may add `false_start`, `repeat`, `semantic`, or `noise` cuts after
reading the transcript. It must leave uncertain material intact. Rewording,
synthesizing speech, or requesting a new performance is not speech edit and
requires the author.

## Non-negotiable safety gates

Every requested cut is resolved again against the PCM signal before FFmpeg is
allowed to edit it:

- a cut that touches only part of a word is retained, never rounded inward;
- both boundaries need at least 35 ms clearance from retained words;
- boundaries snap within a bounded window to the lowest-RMS point;
- a boundary louder than −30 dBFS is considered unsafe and the cut is skipped;
- safe internal joins use a 12 ms overlap-crossfade, preserving room tone;
- the rendered transition is scanned for a click-like sample discontinuity;
  a failed continuity check blocks bundle publication.

This policy intentionally prefers an extra pause or filler over damaged
speech. Skipped decisions are written to `resolution.skipped_cuts`; they are
not silently treated as applied edits.

## Plan contract

Plans use half-open source-time intervals in seconds:

```json
{
  "schema": "dlstudio.speech-edit/v1",
  "input": {
    "audio_sha256": "<generated by --prepare-plan>",
    "words_sha256": "<generated by --prepare-plan>",
    "duration": 12.34
  },
  "cuts": [
    {
      "t0": 2.1,
      "t1": 2.86,
      "reasons": ["false_start"],
      "sources": ["agent"],
      "confidence": 1.0
    }
  ]
}
```

Do not edit the generated hashes or duration. The executor rejects a stale
plan, overlapping/out-of-range cuts, a cut through a retained word, and a plan
that removes the entire take.

## Outputs and recovery

The declared `Beat.audio` and `Beat.words` paths remain unchanged, so compile,
captions, mix, and cache need no special speech-edit support. The CLI stages
the edited WAV, remapped words, and audit artifact before promotion and rolls
the bundle back if publication fails. The raw file in `data/recordings/` is
never touched.

By default, a beat whose transcript is `data/finalize/b01_words.json` receives
`data/finalize/b01_speech_edit.json`. The artifact contains:

- source and output SHA-256 hashes;
- every cut with reason, source, and confidence;
- the executed FFmpeg filtergraph and exact output duration;
- resolved boundary RMS evidence and post-render join continuity metrics;
- every unsafe requested cut that was deliberately retained;
- `maps.old_to_new` and `maps.new_to_old` word-index maps.

After a semantic cut, the agent must use these maps to update every affected
`Chunk.words` and `SfxEvent.word` reference in `beats.py`, then run `dl2 check`.
Deleted captions regenerate automatically from the edited words file. A stale
artifact must never be reused.
